# Markdown Exporter 1.0.0

Markdown Exporter 1.0.0 is the first stable release of the local-first Markdown writing and publishing application. It brings the existing browser editor to Windows, macOS, and Linux as a native Wails desktop app while retaining the browser build and its workflows. The desktop application embeds its frontend resources, so editing and exporting local documents do not require a hosted server, an account, or a network connection after installation and operating-system prerequisites are available.

## What is included

- **A complete writing workflow.** Start from a blank document or a meeting-notes, project-brief, research-report, or how-to template. Rich, source, and inline-Markdown editing share undo behavior, search, citations, custom page setup, mathematical notation, diagrams, and a paginated preview. A new document backs up nonempty writing before replacement; book backups include metadata, chapters, and assets.
- **Manuscript organization.** Manage front matter, chapters, and back matter; reorder and rename sections; inspect outlines; search across sections; and view section and total word counts. Folder projects and `.mdbook` archives preserve their associated assets.
- **Four publication formats.** Export to PDF, DOCX, standalone HTML, and EPUB. Existing page-layout, math, bibliography, citation, image, and manuscript features remain part of the shared application.
- **Native desktop integration.** Open Markdown files, `.mdbook` archives, and folders through native dialogs; save files and exports to chosen destinations; and use the File and View menus for document, export, focus, page-setup, and shortcut commands. Cancelled dialogs preserve the current document.
- **Local recovery and privacy.** The app keeps recovery data on the device and atomically saves desktop drafts in the OS application profile. Windows uses `%APPDATA%/MarkdownExporter`, macOS uses `~/Library/Application Support/MarkdownExporter`, and Linux uses `$XDG_CONFIG_HOME/MarkdownExporter` (normally `~/.config/MarkdownExporter`). Set `MARKDOWN_EXPORTER_DATA_DIR` to select a different local profile.
- **A vector identity.** The folded-folio icon, monochrome mark, and outlined wordmark are original SVG assets. The release includes reproducible desktop icon derivatives.

## Installation requirements

### Windows

Use the portable executable directly or run the NSIS installer. The application requires Microsoft Edge WebView2 Runtime. The installer checks for this runtime and launches Microsoft's WebView2 bootstrapper if it is missing; the bootstrapper needs an internet connection to download the runtime. After WebView2 is present, Markdown Exporter itself can be used offline. A portable distribution intended for a fully disconnected system must be paired with a preinstalled WebView2 Runtime.

### macOS

Download the archive for the computer's processor and extract the `.app` bundle. These 1.0.0 builds are unsigned and not notarized. macOS Gatekeeper may require the user to approve the application from Finder using Open on first launch. A Developer ID signing identity and notarization credentials were not configured for this release pipeline.

### Linux

The Debian package declares `libgtk-3-0` and `libwebkit2gtk-4.1-0` as runtime dependencies and integrates with the desktop application menu. Install it with `sudo apt install ./MarkdownExporter-1.0.0-linux-amd64.deb` or the corresponding ARM64 file. The tarball contains the executable and a short requirements note; install GTK 3 and WebKitGTK 4.1 runtime libraries before launch.

## Offline behavior and known limits

The desktop executable embeds the application interface, fonts, math rendering, and diagram support. The browser application remains separately available as a static site, including its browser service-worker behavior. External links and remote images still need their destinations to be reachable. Portable manuscripts should include their image and bibliography assets in the selected project folder or archive. Recovery data is readable local writing; protect the configured application profile like other personal documents.

The macOS bundles are not signed or notarized. Windows installation of WebView2 may require a one-time network connection when that runtime is absent. Linux desktop packages depend on system GTK and WebKitGTK libraries. These are operating-system prerequisites rather than remote services required by the editor after setup.

## Build and quality assurance

Each package is built on a native GitHub-hosted runner: Windows x64, macOS Intel, macOS Apple Silicon, Linux amd64, and Linux ARM64. The release workflow gates publication on type checking, lint, formatting, unit tests, end-to-end and accessibility tests, Go tests and vet, and successful packaging for every target. It generates checksums after all packages are assembled. The application uses the same frontend implementation in browser and desktop builds; release packaging does not remove the web distribution.

This first stable release includes native save and recovery behavior, grant-scoped local file access, safe replacement writes, and regression coverage for browser and desktop workflows. Please report reproducible defects with the operating system, package filename, and a concise set of reproduction steps.
